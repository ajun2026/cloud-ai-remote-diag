## 二、连接令牌（桥接器唯一化）

**凭证从"房间码"升级为"房间码 + 连接令牌"**：

```
创建房间 → 服务器生成 connect_token（32 位强随机，绑定房间）
    ↓
一键连接（命令/.bat/Linux）自动内嵌令牌
    ↓
bridge 连接 → 提交 房间码 + 令牌 → 服务器校验（匹配 + 未失效）
    ↓
通过才放行；无令牌 / 令牌错 / 已作废 → 拒绝
```

| 要点 | 状态 |
|---|---|
| 服务器只存令牌哈希（防 DB 泄漏） | ⏳ 待实施 |
| 管理员旁路（接管/审计） | ⏳ 待实施 |
| Go bridge 支持 `-token` 参数 | ⏳ 待实施 |
| ps1 支持 `$env:BRIDGE_TOKEN` | ⏳ 待实施 |
| 传统手动输房间码废弃 | ⏳ 待实施 |

## 十、设计权衡

| 项 | 权衡 |
|---|---|
| 令牌 + 结束诊断 | 工程师多一步操作；换来离开即失效 |
| 登录 4h + 空闲 30min | 体验 vs 安全——活跃续期保证干活不打断 |
| 资源限额 | 正常工程师够用；泄漏者消耗封顶 |
| 管理员旁路 | 审计/救场必需；管理员账号用日志+告警重点盯防 |
| 机器绑定（默认关） | 更严但增加换机成本；按需启用 |
| HTTPS 已落地 | 全站加密 ✅——后续安全项在此基础上叠加 |
