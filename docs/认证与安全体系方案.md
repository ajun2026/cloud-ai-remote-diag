---

## 一、背景与现状风险

| 现状 | 风险 |
|---|---|
| 通用 exe + 8 位房间码即可连接 | 房间码可被分享/猜测，弱凭证 |
| 无"离开失效"机制 | 工程师离开后客户机上的 exe 仍有效 |
| 登录有效期 12h，无空闲超时 | 忘关页面 = 身份长期有效 |
| 无登录日志 | 账号泄漏无法及时发现/审计 |
| HTTP/WS 明文传输 | 登录凭证/房间码/令牌/命令可被中间人窃听（最大缺口） |

---

## 二、连接令牌（桥接器唯一化）

### 设计

凭证从"房间码"升级为"**房间码 + 连接令牌**"：

```
创建房间 → 服务器生成 connect_token（32 位强随机，绑定房间）
    ↓
一键连接（命令/.bat/Linux）自动内嵌令牌
    ↓
bridge 连接 → 提交 房间码 + 令牌 → 服务器校验（匹配 + 未失效）
    ↓
通过才放行；无令牌 / 令牌错 / 已作废 → 拒绝
```

### 要点

- **服务器只存令牌哈希**（类似 SSH 公钥登记）——DB 泄漏也无法伪造连接
- 令牌只在连接命令/包里出现，工程师自行保管（离开时点「结束诊断」即失效）
- **管理员旁路**：管理员身份不受令牌限制（接管/审计职责），但管理员账号需更强保护（见第七节）

### 客户端改动

| 端 | 改动 |
|---|---|
| Go bridge | 支持 `-token` 参数 / BRIDGE_TOKEN 环境变量 |
| ps1 | 支持 `$env:BRIDGE_TOKEN` |
| 一键连接 | 命令/.bat/Linux 自动内嵌令牌 |
| 传统手动输房间码 | 废弃（连接必须带令牌） |

## 三、失效机制（三重保险）

| 失效方式 | 触发 | 效果 |
|---|---|---|
| **结束诊断（一键关闭）** | 对话页/工单点「⛔ 结束诊断」 | 令牌作废 + **房间网页不可访问** + 历史封存（管理员仍可审计） |
| 房间有效期到期 | expires_at（已实现） | 令牌自动失效 |
| 令牌有效期 | 生成后限时（如 24h） | 兜底防长期有效 |

「结束诊断」= 一键关闭：**exe 连不上 + 网页打不开 + 历史封存**——解决"工程师离开后"的完整场景。

---

## 四、机器特征绑定（跨平台）

| 平台 | 唯一标识 | 来源 |
|---|---|---|
| Windows | MachineGuid | 注册表 HKLM\SOFTWARE\Microsoft\Cryptography |
| Linux | /etc/machine-id | systemd |
| 兜底 | /var/lib/dbus/machine-id、主板 UUID | 老系统/无 systemd |

- 桥接器统一收集 `machine_id` 字段（平台无关），服务器端登记
- ❌ 不使用：MAC（可伪造）、hostname（可改）、MTM（不唯一）
- 绑定语义：房间首次连接登记机器特征，换机器连接需工程师在网页确认解除
- 可选启用（增加运维复杂度，默认关闭）

## 五、有效期体系（三个维度，独立设计）

| 维度 | 对象 | 建议量级 | 目的 |
|---|---|---|---|
| **账号登录会话** | 工程师账号 | **4h 绝对 + 30min 空闲登出** | 安全：防忘关/离开滥用 |
| **连接令牌** | 桥接器授权 | 24h | 工具：谁能连该房间 |
| **房间有效期** | 工单业务 | 7/15/30 天/永久（已实现） | 业务：诊断生命周期 |

### 登录有效期设计

- **空闲超时为主**：30 分钟无操作（鼠标/键盘/页面切走）→ 提醒倒计时 → 自动登出；有操作自动续期（干活永不掉线）
- **绝对超时为兜底**：4h 强制过期（可收紧到 2h，按测试反馈调整）
- 登出后：页面自动跳登录页，ws 断开

## 六、防资源滥用（账号泄漏防护）

**关键认知**：页面打不开防不了密码泄漏（重新登录即可）——**资源限额才是正解**。

| 层 | 机制 | 效果 |
|---|---|---|
| **资源** | 每账号并发房间上限（2）+ 每日诊断次数上限（20） | 泄漏后资源消耗封顶（釜底抽薪） |
| **入口** | 信任设备/新设备验证（二期可加 2FA） | 别人用自己的电脑登录被卡 |
| **监控** | 登录日志 + 异常告警 | 及时发现泄漏 |
| **止损** | 管理员一键停用账号 | 立即封死 |

---

## 七、登录审计与账号管理

- **登录日志表**：工号 / 时间 / IP / 设备指纹 / 结果（成功/失败）——管理员后台可查
- **异常标记**：非联想网络 IP、新设备首次登录、同账号多地同时登录、频繁失败（防爆破）
- **口令策略**：密码强度要求、失败锁定（如 5 次锁 15 分钟）
- **账号生命周期**：离职停用；管理员强制下线

---

## 八、传输安全（最大缺口，优先）

- **HTTPS/WSS**：当前 HTTP 明文——登录凭证/房间码/令牌/命令全部裸奔
- 方案：Nginx/反代 + Let's Encrypt 证书（或云厂商证书），HTTP 强制跳转 HTTPS
- 一键连接地址随之变为 https:// / wss://（模板注入机制已支持，改动小）

---

## 九、实施优先级（分批）

```
第一批（安全收益最大）：
  ① HTTPS/WSS 传输加密
  ② 连接令牌 + 结束诊断一键关闭（含 Go bridge/ps1/前端改动）
  ③ 登录有效期 4h + 空闲 30min 登出
第二批：
  ④ 登录日志 + 资源限额（并发 2 + 日 20）
  ⑤ 机器特征绑定（machine_id）
第三批（可选）：
  ⑥ 信任设备 / 2FA
  ⑦ 口令策略强化 / 导出管控 / API 限流
```

## 十、设计权衡

| 项 | 权衡 |
|---|---|
| 令牌 + 结束诊断 | 工程师多一步操作（点结束诊断）；换来离开即失效 |
| 登录 4h + 空闲 30min | 体验 vs 安全——活跃续期保证干活不打断 |
| 资源限额 | 正常工程师够用；泄漏者消耗封顶 |
| 管理员旁路 | 审计/救场必需；管理员账号用日志+告警重点盯防 |
| 机器绑定（默认关） | 更严但增加换机成本；按需启用 |
