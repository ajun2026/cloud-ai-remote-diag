# 房间有效期方案

| 项目 | 内容 |
|:---|:---|
| 版本 | v1.0 |
| 日期 | 2026-08-10 |
| 状态 | 待评审 |

---

## 一、目标

创建房间时可选择有效期（7 / 15 / 30 天），过期后房间只读；历史数据永久留档，管理员可见全部。

## 二、交互流程

```
创建房间：SN + 工单号 + 有效期（7天 / 15天 / 30天，默认 30 天）
    ↓
我的工单：每行显示「剩 X 天」（快过期变黄、已过期变红）
    ↓
过期后：不能连接桥接器 / 不能发新消息（历史可查看，数据不删）
    ↓
管理员后台：所有房间可见（含过期状态 + 剩余天数）
```

## 三、数据设计

- rooms 表加 `expires_at` 字段（datetime，可空=永久）
- 老房间兼容：默认按创建时间 + 30 天（或永久，评审决定）
- 创建房间 API 增加 `validity_days` 参数（7/15/30，默认 30）

## 四、过期判定与行为

| 状态 | 判定 | 行为 |
|---|---|---|
| 正常 | 未到 expires_at | 一切照旧 |
| 已过期 | 超过 expires_at | bridge 拒绝连接（提示"房间已过期"）、发消息拒绝（提示只读）；历史记录仍可查看 |

## 五、前端展示

- 工单列表「有效期」列：`剩 23 天` / `剩 2 天`(黄) / `已过期`(红) / `永久`
- 对话页信息栏显示剩余天数
- 创建房间表单加有效期下拉

## 六、技术改动清单

| 位置 | 改动 |
|---|---|
| server.py | rooms 表加 expires_at；创建房间 API 加 validity_days；bridge/消息接口加过期校验；/api/rooms 返回 expires_at/剩余天数 |
| dashboard.html | 创建表单加有效期选择；工单列表有效期列真实显示（badge 颜色） |
| index.html | 信息栏显示剩余天数 |
| 管理后台 | 房间表格显示过期状态（活跃房间/历史记录） |

## 七、验证

1. 创建 7 天房间 → 工单显示"剩 7 天"
2. 手工改 expires_at 为过去 → bridge 连接被拒 + 发消息被拒 + 历史可看
3. 管理员后台看到过期状态
4. 老房间默认值兼容
