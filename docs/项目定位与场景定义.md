## 一、一句话定位

**联想电脑售后场景下的「云端 AI 远程诊断助手」**——工程师用浏览器远程诊断客户电脑，AI 负责"专业知识的执行与解读"，工程师负责判断与处理。

```
客户电脑（执行器 bridge）
    ↕ 一键连接（443/8443 自动降级）
云端（大脑 AI + 工具库 + 房间/账号/审计）
    ↕ 浏览器
工程师（上门 field / 远程 engineer / 管理员 admin）
```

## 二、用户角色矩阵

| 角色 | 是谁 | 干什么 | 权限要点 | 界面 |
|---|---|---|---|---|
| **field** 上门工程师 | 现场服务人员 | 建房间 → 连客户机 → 跑工具 → 出报告 | 连接 + 工具，无对话/历史 | 极简（已交付） |
| **engineer** 远程工程师 | 坐席 / L2 支持 | 对话式 AI 诊断、深度分析、复杂问题 | 全功能 + Tier3 审批 | 全功能工作台 |
| **admin** 管理员 | 项目负责人 | 账号 / 房间 / 安全 / 审计 | 全部 + 管理后台 | 管理后台 |

## 三、核心场景（按优先级）

### 场景 1：现场上门诊断（主场景——今天 field 界面服务的场景）

```
客户报修 → 派单上门 → 工程师现场建房间（选系统）→ 客户机一键连接
→ 按平台跑工具（SIO/SMART/蓝屏/日志/RAID）→ 报告 → 判断处理 → 闭环
```

**关键要求**：现场 10 分钟内完成连接 + 关键诊断；断网/网络被拦可降级（8443）；报告带走（数据不上云原则）。

### 场景 2：远程协助诊断（工程师间协作）

```
客户机在线（已连房间）→ 远程工程师进对话页 → AI 对话式诊断
→ 多工具协同（证据链）→ 结论 + 修复建议 → 远程工程师拍板
```

**关键要求**：AI 只诊断辅助，Tier3 修改操作必须审批；对话历史留存（审计）。

### 场景 3：设备级维护（ThinkStation 专属，远期落地）

```
SN/MTM 刷写、BIOS 相关操作——仅授权工程师/管理员
```

**关键要求**：高风险操作单独授权、操作留痕、防误刷（机器绑定 MachineGuid）。

## 四、场景边界（明确不做）

| 做 ✅ | 不做 ❌ |
|---|---|
| 诊断（只读为主：日志/硬件/系统） | 无人值守自动修复 |
| 受控操作（Tier3 审批） | 终端用户自助（远期愿景，非当前） |
| 报告生成与归档 | 生产级刷机/固件升级（安全风险） |
| 房间/账号/审计体系 | 跨企业开放平台 |

## 五、验收标准（场景是否成立）

| 指标 | 目标 |
|---|---|
| 诊断准确率 | 关键工具（SIO/SMART/蓝屏）真实机器对照通过 |
| 现场效率 | 上门一次诊断闭环（连接 ≤5 分钟，核心诊断 ≤10 分钟） |
| 工程师使用率 | 22 人试用，X 周内产生真实诊断记录 |
| 安全 | 无越权访问、操作留痕可审计 |
